# shop — goods, purchases, clans, personal rooms

- **Owns:** `ShopGood`, `Purchase` (one row = one chain of grant periods), `Clan`, `ClanMember`, `PersonalRoom`, `RoomGuest` (decisions 014 §1, §3, §8; 015).
- **Interface:** `ShopService` in `service.ts` — `overview`, `grants`, `quote`, `buy(userId, goodId, expectedPeriods, input)`, `reconcile`, `reconcileAll`, `expirePass`, `warnPass`, `retryPass`, `memberJoined`, `memberLeft`, `adminList`, `goodBySlug`, `grantByAdmin`, `revokeList`, `revoke`, `configure`, `setEnabled`, `startup`, `devExpireSoon`. `ClanService` (`clan.ts`): `forUser`, `addMembers`, `removeMember`, `leave`, `restyle`. `RoomService` (`room.ts`): `forOwner`, `forPlayer(actor, ownerId)`, `forManager(actor, roomId)`, `update(actor, roomId, patch)`, `addGuests(actor, roomId, ids)`, `removeGuest(actor, roomId, userId)`.
- **Goods (seed, disabled until configured):** `media_access` «Доступ к картинкам и GIF» 5 000 (kind `channel_permission`, AttachFiles + EmbedLinks, one role, one channel list — 015 §2), `clan_role` 15 000, `personal_room` 10 000; all 30 days.
- **Taking a purchase back — `/отозвать` (023):** `revokeList(actor, userId)` and `revoke(actor, { purchaseId, expectedPeriods, refund })`, both behind `SHOP_MANAGE` **checked in the service**, not only in the handler (023 §4). One transaction: `UPDATE … SET status='REVOKED', revokedAt, revokedById WHERE id AND status='ACTIVE' AND periods=$expected` → no row = `STALE_PANEL` → `closeClans` exactly as expiry does → when `refund`, `economy.move(+pricePaid, refund:<id>, REFUND)`, the same reference as the failed-apply refund, so a purchase is refunded **at most once**. After the commit, in this order: the log-channel line (before any reply, so a Discord failure never loses the audit), the convergence pass that takes the Discord grant back, then the player's DM (`grant_revoked`; a closed DM is not an error). The confirm buttons carry `purchaseId` and `periods`, never an amount (002 §4).
- **Handing a good out — `/выдать-товар` (024):** `grantByAdmin(actor, { userId, goodId, days, clan?, roomName?, targetIsBot? })` behind `SHOP_MANAGE`, checked in the service. **`economy` is never called**: a hand-out has no ledger row, so `sum(ledger) = balance` cannot move, and `pricePaid` stays 0 for the period given. A player without the good gets the same insert `buy` makes (`insertGrant`, shared, so the clan lock order has one copy) with `pricePaid` 0 and `precheck` run first; a player who has it gets `periods + 1` and `expiresAt = GREATEST(expiresAt, now) + days` by the same guarded UPDATE the renewal uses, with the expected period count **read in the same transaction** (no panel carries it). Either guard missing its row = `GRANT_RACED`, so two invocations at once add the days once. A good that is forever has nothing to extend (`ALREADY_OWNED`); a disabled good is refused with its name in `params.goodName`; `days` is 1..365 (`DAYS_INVALID`). Then, in order: the log-channel line, the convergence pass, the player's DM (`grant_gifted`). `goodBySlug` resolves the command's choice — a slug, because Discord takes the command's options once at registration and a slug survives a re-seed.
- **Money (014 §1):** new = one transaction (insert Purchase guarded by the partial unique index on ACTIVE (user, good) → clan/room row → `economy.move(-price, purchase:<id>:1)`); renewal = `UPDATE … WHERE periods = expected AND appliedAt IS NOT NULL` → `purchase:<id>:<period>`; refund = `UPDATE … status='REFUNDED' WHERE ACTIVE AND appliedAt IS NULL` → `refund:<id>`. The confirm button carries `expectedPeriods`, never an amount; the price is read at confirm.
- **Discord follows by convergence (014 §2):** a keyed coalescing queue per (user, good) (`core/keyedQueue.ts`). A pass revokes every ended row not yet cleaned (a shared resource is skipped while an ACTIVE row exists), then applies the ACTIVE row and sets `appliedAt`. `buy` waits for its pass up to 8 s. A failed apply is stored in `lastApplyError` (first failure → log channel); after 30 minutes unapplied with the buyer present, the pass ends the purchase and gives back what was paid — **`economy.move` is skipped when `pricePaid <= 0`** (a hand-out, 024): a zero move is refused, and that throw would roll the ending back and leave the pass failing every minute for ever. The log line, the first «пробую каждую минуту» warning and the player's DM then say «возвращать нечего» instead of «0 KP Coin». `precheck` runs on cached guild data before money moves → `SHOP_UNAVAILABLE` plus a log line.
- **Extension point:** `kinds/` — a kind is `configSchema`, `settable`, `guildIdKeys`, `sharedResource`, `validate`, `precheck`, `apply`, `revoke`, `describe` (`kinds/types.ts`), one file plus one line in `kinds/index.ts`. **`guildIdKeys` names every config key holding a Discord id** (`channelIds`, `roleId`, `anchorRoleId`, `categoryId`): `guildIdsPatch` empties them when the bot changes server (`modules/settings/guildChange.ts`), because a role or channel of the old server means nothing on the new one. A kind that forgets to declare one fails `kinds.test.ts`.
  - `channel_permission`: bot-created role with no permissions; per channel `permissionOverwrites.edit` (never `set`): the bot's own allow first, the role allow, the @everyone deny (`discord/accessOverwrites.ts`). A channel taken off the list gets the role overwrite deleted and @everyone/bot back to inherit.
  - `clan_role`: role per clan, placed directly below the admin's anchor role (015 §4; without it the good cannot be enabled), named/coloured only at creation and on the owner's rename; members converge to {owner} ∪ `ClanMember`. Name rules in `names.ts`, admin texts in `problems.ts`.
  - `personal_room`: bot-owned voice channel in the chosen category, locked by default; name, limit and overwrites written in full every pass; the owner never gets Manage Channels. Since 024 §4 every room change takes `(actor, roomId)` — the panel's custom_ids carry the room id — and is allowed to the room's owner **or** a holder of `SHOP_MANAGE`; `/комната <игрок>` opens someone else's panel through `forPlayer`. The single log-channel line a change writes names the administrator and the owner when the actor is not the owner; the owner's own change reads exactly as before.
- **Invariants:** at most one ACTIVE purchase per (user, good); `Clan.memberCount = count(ClanMember)` (0..25, guarded increment + insert); `ClanMember.userId` unique (one clan per person, Q15); open clan names unique case-insensitively (`Clan_open_name_key`); `PersonalRoom.guestCount = count(RoomGuest)` (0..25).
- **Lock order for clans (017 §3):** User rows (ascending) → Clan row(s) `FOR UPDATE` (ascending) → ClanMember rows. Add, remove, leave, a member leaving the server, expiry and the refund (`closeClans`) all follow it; remove, leaving the server, expiry and the refund also run in `withTxRetry` (re-run on a deadlock).
- **Role ids are saved at creation (017 §1):** `ensureRole` awaits `onCreated(id)` before `setPosition`, so a failed positioning never makes the next pass create a second role. A clan rename edits the role only if it exists; a missing role is created by convergence. The refund re-reads the row before deleting the role.
- **Names (`names.ts`, 017 §2, §4):** 2–32 characters of letters, digits, spaces, `-_.!?` and emoji, with at least one letter, digit, pictographic emoji or flag letter (invisible joiners, marks or punctuation alone are refused). Forbidden words match only at the start of a word (start or after a non-letter): «Работа», «Суббота» pass; «Админы», «ModSquad» — and «Modern» — are refused; «ТопАдмин» passes.
- **Leaving the server (014 §3.4, Q17):** a buyer keeps the purchase and its time runs on; `guildMemberAdd` reconciles their keys. A clan member or room guest who leaves is deleted, freeing the seat.
- **Settings:** `/игры → ⚙️ Настройки → 🛒 Магазин` (SETTINGS_MANAGE, checked in the service): media channels, room category, clan anchor role, enable/disable; enabling runs `validate` and is refused while problems remain.
- **Logging:** purchases, renewals, refunds, expiries, apply failures, clan and room changes, configuration changes → the log channel.
- **Depends on:** `economy`, `permissions`, `settings`, `logging`.
- **Tests:** `tests/db/shop/*.db.test.ts` (real Postgres, concurrent), `kinds/kinds.test.ts`, `names.test.ts`, `discord/accessOverwrites.test.ts`.
